# CSNの取得・配送構成（方式A）

ユーザー承認: 2026-11-04「Aですすめて」。今回は未稼働の設定一式を準備する。

## 経路と分離

iCLUSTAの既存7アカウント → CSN専用fetchmailユーザーfetchcsn → 127.0.0.1:25のPostfix → 既存Rspamd → Dovecot LMTP → csnのSieve → csnのMaildir。

既存umeokaの設定ファイルは変更しない。SMTP宛先はcsn@imap.umeoka.co.jpに固定する。旧procmailへの直接配送は新設定に含めない。ユーザーの追加、設定の導入、Sieveの有効化、取得開始は、この設定準備とは別の承認対象。

## 取得設定

- mail.blue.shared-server.net:995、POP3S、証明書検証あり。
- info/shop/auction/store/conform/pay/quote@coolingshop.netの7アカウント。
- 単発サービスとタイマーで実行。終了後15秒で次回を実行し、同じサービスの同時起動を避ける。旧常駐方式の15秒とは完全同一の実行周期ではない。
- 正常な「新着なし」の終了コード1を成功扱いにする。
- 既存のkeepなし/fetchallを初期案に明示し、成功時の取得元削除という現行方針を維持する。実際の取得開始前に改めて確認する。
- SMTP受け付け成功は、最終Maildir保存成功と同義ではない。Postfixキューと最終配送の監視・バックアップを切り替え条件にする。
- パスワードはテンプレートの識別子のみ。実値は新サーバー上で安全に設定し、会話・作業記録には出さない。
- サービスは/etc/csn-mail/enable-fetchがない限り実行されない構成。今回はこのファイルを作らず、タイマーも有効化しない。

## Sieve案

- RspamdのX-Spam-Status: Yes、X-Rspamd-Action: add header/reject、または件名の文字列[SPAM]をINBOX.Junkへ保存。
- 過去のspamフォルダは維持する。新しいINBOX.Junkは既存IMAPSieve学習機構と整合させる。
- 出品・再出品・取り消し等はx_Trashへ保存。discard/reject等のメール破棄・拒否操作は使用しない。
- 既存の日本語分類フォルダ名をSieveのUTF-8名として使う。
- 旧設定の「評価」AND（支払い完了OR支払い手続き完了）という条件は勝手に修正せず案へ引き継ぐ。
- 旧nkfによる文字幅・空白の正規化をSieveで完全再現したとは扱わない。件名条件の意味・空白・MIME・文字幅は後日のサンプル検証で確認する。
- ユーザー希望に従い、今回は構文確認まで。振り分けの実動作テストは後に実施し、その前に有効化しない。

## 導入と復旧

作業用ディレクトリの設定一式だけを準備する。導入時は既存の/home/csn/sieveと/home/csn/.dovecot.sieveの有無・内容を秘密情報を表示せず調査して退避し、上書き前に了承を得る。旧サーバーの取得は切り替えまで稼働を継続。旧新の同時取得は禁止。切り替え失敗時は新側取得を止め、旧側の再開条件と新着メールの所在を確認して戻す。
