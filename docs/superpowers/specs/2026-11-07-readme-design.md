# 運用担当者向けREADME設計

## 目的

このリポジトリを初めて開くサーバー運用・引き継ぎ担当者が、CSNメール移行プロジェクトの目的、現在の状態、安全上の制約、参照すべき手順書を短時間で把握できる入口を作る。

## 対象ファイル

リポジトリ直下の`README.md`を新規作成する。本文は日本語とし、詳細な作業履歴や本番コマンドを重複掲載しない。

## 構成

1. プロジェクト概要
2. 現在の運用状態
3. 旧・新・作業端末の役割
4. 重要な運用ルール
5. 主要ドキュメントへのリンク
6. Git管理と秘密情報の扱い

## 記載方針

- 現在は旧サーバーが本番で、新サーバーは切替準備済み・受信停止中であることを明記する。
- 本番切替は承認制とし、旧側停止、Maildir切替、新側fetchmail開始、削除・清掃を独断で行わない。
- パスワード、秘密鍵、メール本文、移行データをGitへ登録しない。
- 詳細な履歴は`CSN-MIGRATION.md`、本番切替は`docs/runbooks/csn-one-time-cutover.md`へ誘導する。
- READMEは運用入口に限定し、既存文書との二重管理を避ける。

## 完了条件

- 日本語で簡潔に読める。
- 運用担当者が現在の本番サーバーを取り違えない。
- 危険操作の承認境界が明確である。
- 主要文書への相対リンクが有効である。
- 秘密情報や実メールの識別情報を含まない。
